# Automation-first production and incremental delivery

## Implemented slice

Auto is the default in Single and Batch. Assisted adds independent concept/candidate/export checkpoints; Expert retains manual generation, specifications and review. Imported files are analyzed automatically in Auto/Assisted, using the lossless deterministic parser. This never starts GPU work. The actual Runavelle V4 source has 349 unique prompt blocks: 312 primary and 37 FUTURE. FUTURE is now descriptive metadata and all 349 are eligible; this supersedes the previous deselection policy documented in the earlier import release.

Generate All explicitly starts all imported assets. Generate Selected supports targeted automatic production. Missing ordinary dimensions resolve from explicit fields, project Art Bible, approved related assets, validated local semantic suggestions and provisional category defaults. Provenance distinguishes explicit/inherited/inferred/defaulted values. Estimates never become verified gameplay contracts or human confirmations. Maximum steps, resolution, seeds, configured candidate count, PBR and required Blender stages use the existing Single Asset resolver.

The automatic coordinator calls the existing concept and image-to-3D endpoints. Provided image references can bypass concept generation; otherwise local SDXL produces a real concept. Hash-bound technical selection allows Auto to continue without inserting a fake human approval. Image pixel count and Laplacian variance are technical proxies, not artistic scoring. Processed candidates are ranked transparently by texture/UV/winding availability, with a documented stable tie fallback. Every candidate and original source remains in Library. Artist approval and approved masters remain separate.

The installed textured TRELLIS.2 community adapter is pinned when suitable. A specifically selected unavailable/incompatible engine blocks that asset instead of silently substituting. Multi-engine candidates are used when compatible engines are pinned for the actual input. There are no invented benchmark quality numbers or paid fallbacks. Existing community-model/provenance restrictions remain; exported evaluation artifacts are not automatically cleared for commercial use. Ollama semantic inference remains optional and unavailable on the audited machine.

The old SDXL worker rejected prompts over 1,200 CLIP tokens, which affected 312 source prompts. Full-window conditioning now accepts up to 64 windows; the measured file maximum is 1,903 tokens / 26 windows before project suffixes. No source is truncated. The new limit is explicit; exceeding it still fails instead of dropping prompt content. Long conditioning does not establish artistic fidelity.

## Queue, pause and recovery

One logical batch remains visible while only a bounded asset window is admitted (default two assets; configurable one to four). One heavy GPU stage uses the shared process-safe resource lock across Single, Batch and separate desktop libraries. CPU Blender/validation can overlap when RAM permits. Stored jobs, attempt identity and per-stage checkpoint states live in SQLite; no in-memory-only queue replaces them.

Pause stops new stage admission and lets an admitted stage reach its checkpoint. The dashboard distinguishes pausing and safely paused. Queued stages in safely paused batches survive normal desktop close. Startup reconciles completed, checksum-validated artifacts, blocks interrupted stages, and defaults to waiting for manual Resume. Explicit auto-resume opt-in applies to existing project batches; explicit user pause is never revoked. Engines are not claimed to resume diffusion tensors. An interrupted unsupported stage starts a new bounded attempt with unchanged settings; finished stages are reused. Atomic Blender-child admission repairs a crash between inference completion and postprocessing admission.

Transient retries are bounded (default one); OOM never lowers quality. Permanent failures remain visible and do not prevent later assets. Pause/Resume/Cancel/Retry Failed/Skip Failed are separate. Disk reserve checks cover Library, workspace and configured output root; hitting reserve pauses new work without deleting sources. ETA remains unavailable when evidence is insufficient. Background tray execution and automatic storage cleanup are not implemented.

## Selective export and game delivery

GLB Only is the default: one self-contained GLB per successful asset, optional manifest enabled, ZIP/FBX/BLEND/separate textures/native packages disabled. Export preferences never change generation settings or remove internal sources. Unity/Full Source/Custom can use actually available validated files; unsupported Unreal native export is disabled. The original conversion/ZIP endpoints remain available under advanced controls.

Each processed, technically validated asset is exported immediately instead of waiting for the batch. Output paths are project/asset/version scoped with sanitized source-ID-based filenames and identity suffixes. GLB is validated with a separate loader, copied to a temporary file, checksum-checked, then atomically renamed. Completion is recorded only after requested outputs and the optional project manifest are published. The project manifest is atomically updated per asset and contains relative paths, actual measured bounds, units/orientation, SHA-256, version history and recorded generation provenance. It is a machine-readable delivery index, not a claim of game readiness.

Re-export uses existing outputs and enqueues no AI. Version directories are immutable. Changed game files or unmanaged/modified project manifests cause an explicit conflict; they are not overwritten. Crash recovery reconciles unchanged files and a manifest renamed just before a SQLite commit. Previous source versions can be re-exported to restore an older project-manifest pointer. No game Git commit, scene modification or deployment is automatic. A native folder picker grants Explorer access to chosen output roots without restarting the backend.

## UX fixes and limits

Generate All uses a prominent sticky action bar; Single also has a visible header Generate button. Actual active-stage indicators animate without inventing percentage progress, and respect reduced motion. Sidebar Create and its keyboard shortcut open a new draft; opening a Library asset remains explicit. Project edits preserve workflow/export presets. Batch components are isolated by project, Auto specification messages do not demand manual confirmation, and completed/Needs Review filters include exported models.

Verification uses the real Downloads file, actual local inference and Windows EXEs. `desktop/verify-auto.mjs` covers auto-analysis, all 349/FUTURE inclusion, sticky Generate, real textured GLB selective export/hash, new Create, forced owned-app shutdown, manual-recovery defaults, job identity and graceful relaunch. `scripts/verify_auto_production.py` runs only three representative assets (House T1, Archer Tower T3, FUTURE Forest Watch Post), verifies incremental export and backend restart/Resume. `desktop/verify-single-auto.mjs` exercises the actual one-click Single Maximum pipeline. Reports distinguish queue admission, native smoke, real GPU output, technical validation and artistic approval. No full 349-asset inference run is launched for development acceptance.

Limits: no Meshy geometry/PBR parity claim; no human artistic approval implied; native Unreal remains deferred. Tested Unity profile remains 6000.4.8f1 / Built-in, not every Unity/URP/HDRP version. Final evidence locations and measured timings are recorded separately after each test finishes.
