# Decisions

- 0.9.5: add measured LOD surface evidence without changing master geometry, ratios, quality lock or texture budgets. Normalize only the reported distances, never independently normalize models for comparison. Keep sampled error distinct from artistic/texture/silhouette certification. Actual bake completion alone cannot justify enabling normal/AO production processing.
- A failed Unity Package Manager IPC startup may relaunch the same Editor stage once, preserving the original failed log and exact command fingerprint. No upstream AI/Blender regeneration or quality downgrade; permanent content/license failures remain visible.

- The 2026-10-22 Adaptive 3D Production + AI Quality Control user specification supersedes the prior proposal of adding mandatory VLM gates everywhere.
- Technical/mandatory structural validation is authoritative; uncertain aesthetic observations are advisory in Auto. Never turn uncertainty into artistic approval.
- Reuse the existing coordinator, SQLite, scheduler, status dimensions, Library and revision/export transactions.
- Diagnose each failed stage from actual logs before changing engines. Repeating a missing dependency with a new seed is not recovery.
- Architecture may use verified parametric geometry when it satisfies declared requirements; do not force all architecture into Blender or downgrade a required photoreal/AI-textured/exact-image route.
- Image interpretation and geometry planning are separated so a style reference cannot silently become the target object. Their results remain inferred and reviewable.
- Keep user Library untouched during acceptance. No unrelated Video/Audio expansion work in this task.
- Retain the real historical tower as a hash-bound regression baseline. A shape-reference request always retains image-to-3D; the narrow authored castle route is not an artistic quality replacement. Replays use explicit original settings and separate output directories. Never lower quality to clear a queue/resource failure.
- Permanent admission/delivery exceptions stop repeated polling retries for that asset until explicit Retry; manual approval checkpoints remain separately reevaluated. Quarantined queued stages and terminal concept blockers do not reserve the logical asset window.

- 2026-10-23: Text routes generate a concept tournament (Maximum 3, Balanced 2, Fast 1; per-item `concept_candidates` override) and rank only eligible concepts (cropped/too-small concepts are never promoted). User-provided references are not ranked or gated. Project style anchors use IP-Adapter Plus SDXL at 0.35 by default; the anchor identity and scale are locked in the effective configuration.
- 2026-10-23 (user instruction): Auto production must not wait for user input; prompt → Generate always continues to a result. When concept layout screening rejects every concept after the bounded repairs, Auto continues with the least-defective concepts; when no concept keeps the whole subject in frame, it continues with the best-ranked one. Each such choice is recorded in `automation.auto_decisions` (stage, decision, reason, kept artifact IDs, `artistic_approval: false`) and shown as "Auto-decided" in Production. Remaining stops are only real impossibilities (empty prompt, no verified engine, failed stages beyond the retry budget, the procedural castle structural contract), explicit user cancellation, and Assisted/Manual Approval checkpoints the user opted into.
- 2026-10-23: Composition policy 5: manifest-format prompts restate their heading with the visual description later in the document ("MANA WELL T2 Runic Conduit. Tiered hexagonal mana fountain…"); that description now joins the heading in the first CLIP window and in the layout-check subject. Without it SDXL plus the watchtower style anchor drew towers for non-tower assets.
- 2026-10-23: Composition policy 6 (measured): manifest-format prompts condition the concept image only on heading + restated visual description + framing + style. Real SDXL A/B at seed 42 with the production windowed encoding (26 windows): mean-all pooling and first-window pooling both turned "Ember Highlands Tree_01" into a tower and "Mana Well" into a castle/tower sheet; the subject-only window produced the tree and the hexagonal fountain. InstantStyle style-block-only IP-Adapter was also measured and was worse (multi-view sheets), so the global 0.35 anchor stays. Evidence: scratch A/B grids (not committed); originals remain immutable in the asset/spec.
- 2026-10-23: Style profile (default style transfer). The project/request style anchor is analyzed once on CPU into a shape-free profile: measured palette + Qwen3-VL materials/finish/rendering with structural words removed. Concepts are conditioned on that text only; the anchor image no longer enters SDXL (IP-Adapter stays available as Settings → Style transfer → Image). Measured (48 images, 4 subjects × 6 variants × 2 seeds): IP-Adapter transferred silhouettes (potion → lantern tower, tree doors, fountain spire); InstantStyle style-block injection was worse (multi-view sheets); text-only kept the requested shape but drew sets of objects more often, so the negative prompt and the layout check now reject multi-object images. Real batch: Mana Well T2 lost the copied spire; Swordsman kept the Runavelle navy/bronze palette.
- 2026-10-23: Cross-asset style kit. The same anchor/profile feeds 3D concepts, 2D sprites (plus hue-preserving Lab harmonization at 0.5), World Plan terrain colours (or a chosen reference image's palette; still requires plan approval) and an optional VFX accent (only a palette colour with saturation ≥ 0.35; capped blend 0.5 so the element keeps its colour family). A deterministic guard routes "match these…/phù hợp với…" requests, or a requested subject unrelated to the image, to style use so the reference is never rebuilt.
- 2026-10-23: Animation-ready by default (composition policy 7). Characters and creatures (classified from the subject in English/Vietnamese; buildings and explicitly posed requests excluded) get a rig-friendly concept pose: humanoids front-view A-pose with arms clear of the torso, creatures a neutral stance with limbs straight, wings flat and tail extended, following A-pose rigging guidance (Lee & Liu 2024; vendor rigging docs). After 3D, the non-blocking game-integration gate records measured rig-readiness evidence: chest-height silhouette arm gaps (width alone is fooled by held weapons) and mirrored voxel symmetry. A humanoid without clear arms is FLAGGED_UNCERTAIN. No skeleton/skinning is produced or claimed; local auto-rigging (UniRig, Make-It-Animatable) awaits license verification.
- 2026-10-23: Requested colours outrank the style palette in the concept tournament (policy 2): colour words from the user's own text (original + literal translation, never the planned design) score by measured hue share; palette similarity drops to a small weight.
- 2026-10-23: Real-world size. Create has a Size & scale preview (new object as a box or the actual model next to a 1.8 m human and selectable references: ~40 common types plus project assets with measured sizes); "Use this size" sends explicit target dimensions and the delivered model is scaled uniformly to the height. Batch never needs per-item previews: an asset-type size table (head-noun detection in English/Vietnamese, strongest of boss/giant/small modifiers) fills provisional sizes at start and again after prompt analysis from the interpreted subject; explicit, inherited and measured sizes are never overwritten, and an explicit height keeps the type's proportions. The Batch scale lineup shows every selected asset to scale per size band.
- 2026-10-23: Auto-rigging candidates checked: UniRig (code MIT, weights MIT on Hugging Face, ~8 GB VRAM, GLB/FBX in, skeleton + skin out, humanoids and creatures; Windows support unstated) is preferred over Make-It-Animatable (code MIT, trained on Mixamo data, humanoid focus). Local Windows install/smoke is being evaluated separately; nothing is integrated until a real rigged output is verified.
- 2026-10-23: Auto-rigging (experimental). UniRig (commit 6793c66, code and weights MIT) runs natively on Windows in its own venv (C:\Users\Winka\Tools\unirig; torch 2.8 cu128, Windows wheels for spconv/torch_scatter/torch_cluster/flash_attn, triton-windows). Measured on a real character: 28-joint humanoid hierarchy, every vertex weighted, ~4 min, ~6.4 GB VRAM. After a character/creature is delivered, Auto queues a GPU 'rig' job that produces a separate "Rigged copy (experimental)" artifact; it is a side branch excluded from delivery state, failures and the admission window, and the master/game delivery is untouched. Project setting auto_rig=false opts out.
- 2026-10-23: Character/creature concepts use SDXL portrait (832x1216) / landscape (1216x832) buckets; square frames made every full-body knight touch the frame. Concept ranking (policy 5) scores every concept, penalising frame contact, character sheets (second figure >= 0.5 of the first) and detached clutter, so a fallback picks the least-bad image; frame contact uses deviation from a locally smoothed side so render vignettes are not mistaken for contact. A requested colour or no in-frame concept earns up to two extra concepts with a targeted directive. Corner watermarks are a soft layout issue (they rejected both red dragons that matched the request).
- 2026-10-23: Prompt planning never invents exclusions or camera/pose words, retries once on length and otherwise keeps the validated English translation; a total interpretation failure leads with a deterministic English subject for Vietnamese requests.
- 2026-10-23: Hunyuan3D-2.1 (shape DiT, local install at C:\Users\Winka\Tools\hunyuan3d21) GPU-verified on the watchtower reference: 16 s load, 75 s generation, 7.73 GB peak VRAM, 715,504 faces, clean silhouette with roof, battlements, gargoyles, balconies and windows on all sides. It is shape-only (no PBR texturing installed; Hunyuan3D-Paint not installed) and its license excludes the EU, UK and South Korea, so TRELLIS.2 stays the textured default; Hunyuan remains a candidate geometry-only route pending a measured geometry comparison and a license decision.
- 2026-10-24 (user decision 1A): Held weapons and shields are separate assets. A humanoid character's held items (explicit or implied: swordsman -> sword, archer -> bow, spearman -> spear, mage -> staff; English and Vietnamese) become companion batch items in the same style and quality, sized by the asset-type rules and tagged with the hand socket they attach to (weapons right_hand, shields/bows left_hand); the body concept carries an empty-hands directive and the item names as negative terms, including tournament and layout repairs. Props are never split, and a project can opt out with separate_held_items=false. Decisions 2 (Hunyuan3D stays a non-default, shape-only candidate) and 3 (auto-rig on by default) follow the recommendations.
- 2026-10-24 (user instruction): Working files are deleted after a game delivery by default (project setting cleanup_intermediates, Settings > "Working files after delivery"). Only terminal jobs of the delivered asset are touched: raw_master.npz + checkpoint receipt, render-pass EXRs, .blend scenes, LOD1-3, FBX and separate textures (the last four kept when an export setting requests them, FBX/textures also for Unity packages). Registered artifacts (raw.glb, processed LOD0, concepts, checks) stay, so the Library, re-export, rigging and uniform-scale revisions still work; re-finishing from the TRELLIS checkpoint does not. Measured on HOUSE T1: ~800 MB -> ~160 MB per asset. Staged revisions are not cleaned.
- 2026-10-24: RAM admission lets a lone GPU stage start up to 6 GiB below its physical allowance (Windows pages idle apps; slower, quality unchanged). The Windows commit check still requires the full allowance + 2 GiB, so the stage cannot run out of memory; any other live claim restores the strict gate.
- 2026-10-24 (user request): "Keep final GLB only" (asset panel, explicit confirm). Allowed only after a verified game delivery of the published version with no running work. Keeps the published artifact, its delivered export, rigged copies and the thumbnail render; deletes every other job file (JSON receipts stay) and their artifact rows. Later changes need a new generation.
- 2026-10-24 (user request): "Allow questions" switch (Create and Batch Auto, per-user, default off). When on, a light CPU job (local Qwen3-VL, ~16 s) asks up to 10 questions, most important first, before prompt analysis; short prompts (<12 words) get at least 4, detailed prompts usually none. Questions about colour or size/role are dropped when the request already names a colour or boss/giant/small. The asset waits alone (it does not hold an active-asset slot); Production lists pending questions with options, free text and "AI decides from here". Answers are appended to the immutable original prompt as user-confirmed details for prompt analysis; unanswered questions are left to AI. Off: unchanged automatic decisions. Real Qwen check: "tạo 1 con rồng" -> type, colours, size/role, features; "boss ... rồng khổng lồ đỏ" -> type, features; detailed barrel prompt -> none.
- 2026-10-24 (user request): "Prompt examples" in Create and Batch: an attribute checklist with Single examples, a Batch field guide, and the same five assets in each import format (heading blocks, Markdown table, CSV, JSON), viewable and downloadable. tests/test_prompt_examples.py imports every batch example; it exposed and fixed CSV numeric cells (game_texture_size, triangle_budget, ...) arriving as text.
