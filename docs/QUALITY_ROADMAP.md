## Implementation order and acceptance

1. Prompt requirements: preserve explicit source excerpts, immutable prompt/model hashes and revision deltas. Measure real GLB dimensions; expose unresolved visual checks honestly. Auto remains unattended. Native acceptance uses the actual generated Archer and an actual CPU scale revision.
2. Consistent modular/material vocabulary: reuse project-scoped styles and verified components; preserve constraints across revisions.
3. One Unity combat/effect slice: native editable shader/mesh/trail recipe, meaningful timeline preview and real GPU captures/cold reopen. Reuse the global GPU scheduler. Validate effect timing independently before claiming complete character combat animation.
4. Rig and animation: use a licensed rigged source, validate skinning/retarget/contact/root motion/loop seams and native clips. A procedural weapon demonstration is not a validated humanoid or AI character generator.
5. Element recipes: distinct shape/motion/timing per element, tested output variants and platform budgets. No color-only claim of complete elemental behavior.
6. Small assembled Runavelle environment: extend existing World Plan rather than replacing it; real collision/navigation, asset coherence and camera gameplay checks.

Every slice records actual supported target/version, real artifacts, limits and failures. Unsupported outputs remain unavailable. No paid inference, cloud fallback, automatic model downloads, fabricated confidence scores or automatic artistic approval.
